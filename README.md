## 🏗 Архитектура
<a name="архитектура"></a>
- **Микросервисный подход:** Модульное разделение логики транспорта, валидации и обработки данных
- **Очередь интеграции:** Промежуточный слой хранения данных для гарантии доставки и снижения нагрузки
- **Централизованные настройки:** Единое ХранилищеЗначений для управления конфигурацией системы

---
Система построена на принципах многослойной архитектуры с разделением ответственности между транспортным уровнем, слоем хранения и бизнес-логикой.

### 📐 Схема взаимодействия
```text
       [ КЛИЕНТСКИЙ СЛОЙ (UI) ]

                  |
                  v
       [ СЕРВЕРНЫЙ СЛОЙ (ЮклайнсAPI) ]
                  |
        --------------------------

        |          |             |
        v          v             v
  [ ОЧЕРЕДЬ ]  [ МЕТРИКИ ]    [ ЛОГИ ]
  (Регистр)    (Регистр)     (Журнал)
        |
        v
  [ ОБРАБОТКА ОЧЕРЕДИ ] ----------> [ YCLIENTS API ]
   (Бизнес-логика)       (HTTPS)
```

### 🔹 Описание слоев
- **Транспортный уровень (ЮклайнсAPI):** Инкапсулирует логику HTTP-запросов, авторизацию и первичную обработку JSON.
- **Data Layer (Хранение):** 
    - **Очередь интеграции:** Транзакционное хранилище для асинхронной обработки.
    - **Метрики:** Сбор телеметрии (Latency, Error Rate, Размер пакетов).
- **Business Logic (Обработка):** Десериализация данных и актуализация прикладных объектов 1С.

| **ЮклайнсОбработкаОчереди** | Диспетчер: обработка входящих пакетов из очереди интеграции | `CommonModules/ЮклайнсОбработкаОчереди/Module.bsl` |
| **ЮклайнсОчередьСервер** | Служебный модуль: низкоуровневые операции с регистром очереди | `CommonModules/ЮклайнсОчередьСервер/Module.bsl` |

## 🛡 Инфраструктура
<a name="инфраструктура"></a>
- **Circuit Breaker:** Защита от сбоев внешнего API с режимом самовосстановления `HALF_OPEN`
- **Retry Mechanism:** Повторы запросов с экспоненциальной задержкой (Exponential Backoff)
- **Observability:** Сбор данных о Latency, Error Rate и размере пакетов в реальном времени
- **Fault Tolerance:** Глубокая обработка сетевых исключений и системных ошибок

### 🛡 Механизм защиты: Circuit Breaker
<a name="circuit-breaker"></a>

Паттерн предназначен для предотвращения каскадных сбоев в системе при нестабильной работе внешнего API.

#### Принцип работы (Алгоритм):

```text
       [ Запрос к API ]

              |
              v
    { API разблокирован? } 
              |
      -----------------

      |               |
     (Да)            (Нет)

      |               |
      v               v
 [ Выполнение ]    [ Отказ с ошибкой ]
 [  запроса   ]    [ "API заблокировано" ]

      |
      v
 [ Код ответа ]
      |
      ---------------------------

      |                         |
  200 (Успех)          429 / 5xx / 999 (Ошибка)

      |                         |
      v                         v
 [ Разблокировка ]        [ Блокировка ]
 [     API       ]        [  на N минут ]
```

#### ⚙️ Параметры блокировки


| Параметр | Описание | Настройка |
| :--- | :--- | :--- |
| **Время блокировки** | Время, на которое API уходит в спячку при сбоях | `ЮклайнсБлокировкаВремя` (30 мин) |
| **Коды блокировки** | HTTP-статусы, инициирующие разрыв цепи | `429 (Too Many Requests), >=500, 999` |
| **Код снятия** | HTTP-статус для восстановления связи | `200 (OK)` |

#### 💻 Реализация Circuit Breaker (BSL)

```bsl
// Проверка блокировки перед выполнением запроса
Если ЗначениеЗаполнено(БлокировкаДо) И ТекущаяДата() < БлокировкаДо Тогда
    Логирование.Ошибка("API ЮК заблокировано до " + БлокировкаДо);
    Возврат;
КонецЕсли;

// При успешном ответе — сброс предохранителя
Если КодСостояния = 200 Тогда
    Константы.ЮклайнсБлокировкаДо.Установить('00010101');
ИначеЕсли КодСостояния = 429 Или КодСостояния >= 500 Или КодСостояния = 999 Тогда
    // Активация защиты
    Константы.ЮклайнсБлокировкаДо.Установить(ТекущаяДата() + ИнтервалБлокировки);
КонецЕсли;
```

### 🔄 Retry механизм
<a name="retry-mechanism"></a>

Для обработки кратковременных сетевых сбоев реализована политика повторных запросов с использованием **Экспоненциального бэк-оффа** (Linear/Exponential Backoff).

#### 📈 График задержек


| Номер попытки | Задержка | Формула |
| :--- | :--- | :--- |
| 1 | 5 сек | `БазоваяЗадержка * 1` |
| 2 | 10 сек | `БазоваяЗадержка * 2` |
| 3 | 15 сек | `БазоваяЗадержка * 3` |
| ... | ... | ... |

#### 🛠 Параметры Retry


| Параметр | Описание | Настройка |
| :--- | :--- | :--- |
| **Max Retries** | Максимальное количество попыток до отказа | `ЮклайнсМаксПовторов` |
| **Base Delay** | Базовый интервал между запросами в секундах | `ЮклайнсЗадержкаПовтора` |

## 📥 Очередь интеграции
<a name="очередь-интеграции"></a>

Для обеспечения асинхронности и гарантии обработки данных используется механизм промежуточного хранения (Staging). Это позволяет системе переваривать большие объемы данных без потери транзакционной целостности.

### 🔄 Жизненный цикл записи
Статусная модель гарантирует, что каждая запись пройдет полный путь от получения до фиксации в базе данных.

```text
 [ Новый ] ----> [ В работе ] ----> [ Обработан ]
    🆕              ⚙️                 ✅

                       |
                       v
                   [ Ошибка ]
                      ❌
```

### 📋 Статусы обработки


| Статус | Описание |
| :--- | :--- |
| **Новый** | Запись успешно загружена из API и ожидает первичной обработки |
| **В работе** | Запись захвачена процессом обработки (защита от двойного захвата) |
| **Обработан** | Данные успешно десериализованы и записаны в прикладные объекты 1С |
| **Ошибка** | Критическая ошибка при обработке (в регистре фиксируется текст исключения) |

### ⚙️ Параметры обработки



| Параметр | Описание | Настройка |
| :--- | :--- | :--- |
| **Размер пачки** | Количество записей, обрабатываемых за один такт регламентного задания | `ЮклайнсРазмерПачки` |

## 📊 Метрики и логирование (Observability)
<a name="observability"></a>

Система поддерживает концепцию **Full-cycle Observability**, обеспечивая прозрачность работы всех узлов интеграции в режиме реального времени.

### 📝 Уровни логирования
Логирование разделено на уровни для эффективной фильтрации и быстрого реагирования на инциденты.


| Уровень | Описание | Пример использования |
| :--- | :--- | :--- |
| **Информация** | Обычные штатные операции | Успешная загрузка данных |
| **Предупреждение** | Важные события, требующие внимания | Близость к лимитам API |
| **Ошибка** | Сбои, не прерывающие работу системы | Ошибка валидации отдельного объекта |
| **КритическаяОшибка** | Системные сбои | API недоступен, Circuit Breaker сработал |

### 📈 Типы метрик
В специализированный регистр накапливаются количественные показатели для анализа производительности (Latency & Throughput).


| Метрика | Описание | Измеряемые показатели |
| :--- | :--- | :--- |
| **API** | Телеметрия HTTP-запросов | Время выполнения, код ответа, размер данных |
| **JSON** | Производительность парсинга | Время десериализации, объем пакета |
| **CircuitBreaker** | Статистика защиты | Время блокировки, причина срабатывания |
| **Очередь** | Эффективность обработки | Размер пачки, время обработки записей |

### 🗄 Хранение данных мониторинга


| Тип хранения | Объект 1С | Описание |
| :--- | :--- | :--- |
| **Детальное логирование** | Регистр `ЖурналЛогирования` | Подробные события, сообщения, доп. данные JSON |
| **Метрики** | Регистр `ЮклайнсМетрики` | Числовая статистика по всем операциям |
| **Системный журнал** | Журнал регистрации 1С | Критические ошибки и системные события платформы |

| Параметр | Описание |

## 📁 Структура проекта
<a name="структура-проекта"></a>

Проект организован в соответствии со стандартами разработки подсистем 1С. Основная логика вынесена в специализированные общие модули.

```text
src/
├── Configuration/          # Основная конфигурация
├── Subsystems/             # Подсистемы
│   ├── Общая/              # Общая подсистема
│   └── Интеграция/         # Подсистема интеграции
├── Catalogs/               # Справочники (Номенклатура, Мастера и др.)
├── Documents/              # Документы (ОказаниеУслуг)
├── InformationRegisters/   # Регистры сведений (Очередь, Метрики)
├── AccumulationRegisters/  # Регистры накопления
├── CommonModules/          # Общие модули (Бизнес-логика)
│   ├── ЮклайнсAPI/         # Модуль работы с API YClients
│   ├── ЮклайнсДанныеСервер/ # Обработка данных визитов
│   ├── ЮклайнсОбработкаОчереди/ # Диспетчеризация очереди
│   ├── ЮклайнсОчередьСервер/# Работа с регистром очереди
│   ├── ЛогированиеПриложений/ # Клиентское логирование
│   └── ЛогированиеСервер/   # Серверное логирование
├── Enums/                  # Перечисления (Статусы, Виды объектов)
├── Constants/              # Константы (Настройки системы)
├── DataProcessors/         # Обработки (Панель управления)
└── README.md               # Документация проекта
```

## 📸 Визуализация работы системы
<a name="скриншоты"></a>
